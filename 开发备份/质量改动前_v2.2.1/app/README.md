# 守忆 LLM记忆工作台

本应用由大模型阅读记忆守则并决定每轮记忆操作。官方28轮和自由试验使用同一条LLM处理链路；没有本地中文提取规则、预置字段答案或模型失败后的离线替代结果。

当前守则为v2.2.1。2026-10-15 22:33:46至22:35:19（北京时间），已从空白记忆完成DeepSeek官方材料28轮真实重跑：28次尝试、28个唯一供应商请求标识，本次完整运行内无重试。当前 `data/official-llm-run.json` 与根目录 `memory-LIMING.md` 来自该次运行，没有手工修改事实、状态或时效。与首轮比较见 `本次重跑对比.md`。

此前v2.2中断调试保存6轮成功结果、共8次尝试，第7轮两次因确认标记不符合协议而被原子拒绝，已独立备份。因此本次调试及最终重跑合计36次尝试，不能描述为整个过程没有失败。失败两次的用量未保留，不能给出全部调用用量或总费用。

## 启动与配置

需要Python 3.10或更新版本，无第三方Python依赖。双击本目录的 `start.bat`，打开终端显示的本机地址。也可执行 `python app.py`；端口被占用时使用 `python app.py --port 8138`。

在侧边栏“模型设置”填写兼容Chat Completions的接口地址、模型名称和API密钥。例如DeepSeek配置为 `https://api.deepseek.com` 与 `deepseek-flash`。密钥仅保存在服务进程内存，不写入源码、浏览器存储或交付文件；重启服务需重新填写。使用第三方模型会产生相应API费用。

应用从上一级交付根目录读取 `memory-rules.md`，作为每次请求的常驻系统指令。模型同时接收当前角色的有效及存疑记忆，以及最多8轮必要的近期对话。完整长号码和密钥在发送前隐藏；第三方来源的请求不携带主人已有的私密记忆。

守则、模型协议和Python代码在启动时加载。当前服务已重启加载v2.2.1并完成上述运行；后续修改需要重启，浏览器刷新本身不能加载新版后台守则。重启会清除仅存在内存中的API密钥，需要重新配置。

## 官方28轮真实运行

1. 配置模型后，在官方实跑页点击“调用LLM运行28轮”。
2. 应用从空白角色记忆开始，逐轮发送官方原始输入的脱敏版本。主人背景卡不参与输入，也不预填事实。
3. 每轮由模型返回决策、操作、逐字证据、原因、守则条款与助手回应。程序校验输出结构和来源权限后，原子执行该轮操作并保存快照。
4. 模型调用、格式或证据校验失败时停止，不保存半轮结果，不改用本地规则。页面展示失败原因；保持同一守则、输入与模型配置时可以从失败轮继续。
5. 只有28轮完整成功后，才在交付根目录生成 `memory-LIMING.md`。更早轮次的下载文件带轮次后缀，不能混称为最终记忆。

`data/official-llm-run.json` 在真实运行后产生，保存已执行轮次的状态、操作与模型请求元数据。重启后可回放这些实际结果，无需再次付费调用。它是本应用的运行记录，不是TeleAgent导出的 `log.json`。

重新运行28轮会再次调用模型并产生费用。旧最终记忆会移入本机运行状态目录，新的最终记忆要等新一轮完整运行结束后才能生成。界面会提示守则摘要是否仍与当前文件一致。

## 操作方式

桌面从左到右为“1 对话列表”“2 对话与处理”“3 当前记忆”。中栏显示真实模型回应、本轮操作的原值和现值；右栏显示结果快照、状态和来源。点击执行依据可查看模型引用的守则条款及完整守则原文。

官方回放中直接输入会自动建立独立分支；也可点击“新建试验”从空白开始。分支与其他工作区独立。界面的确认和删除按钮也会把请求交给LLM决策，再执行模型返回的操作。

来源选择用于模拟主人、第三方、推送与系统入口，不代表真实登录鉴权。真实多用户部署仍需要账户认证和服务端角色绑定。

## 时效与临时事项

五种记忆状态保持不变。每次模型写入或更新会另行给出 `validity`：`kind` 为 `ongoing`（持续适用，可变更）或 `temporary`（短期或阶段性有效），`reference_turn` 为原时间表达或适用条件所在轮次，`time_text` 保存有依据的原话时间表达，`end_condition` 保存有依据的结束条件。没有明确日期或条件时允许空字符串，不能编造。重要的短期任务仍可为ACTIVE，短期传闻仍应为UNVERIFIED。

模型根据守则判断完成、撤销与过期：完成后使旧待办失效，另存有长期价值的结果；明确撤销按forget；已过期限不等于已完成，由模型结合后续责任和价值决定review、invalidate或合理forget。程序只校验对象结构并保存，不解析日期、不根据宿主时间自动删改、不设置本地语义规则。本应用没有后台计时提醒或推送，下一轮有输入时由模型结合可信上下文复核；模拟材料缺少真实日历锚点时不按电脑日期判过期。

卡片、操作变化和Markdown导出展示时效；状态筛选与时效筛选可以组合。旧v2.0记录没有 `validity`，显示“未标注”，不会被自动补标。推送和第三方消息的权限不因带有期限而改变，不能自动写入主人档案。遗忘操作也清除该事项全部版本、快照和变更中的时效细节，清理范围仍是当前工作区。

## 程序与模型各自负责什么

- LLM负责理解原话、判断长期价值、生成和复用属性、同属性更新、关联复核、失效、遗忘、污染识别、查询与回应。
- 程序负责API调用、最小化脱敏、JSON结构与证据检查、来源权限边界、事务保存、删除清理、快照和文件序列化。
- 程序不根据“搬家”“PMP”“裁员”等中文关键词决定记忆操作；不提供固定属性提取表；不在模型失败时补写答案。
- 模型输出仍可能误记或漏记。记录请求标识和版本摘要用于追踪运行来源，不等于模型事实判断已被独立验证。
