# 守忆 SHOUYI

以官方赛题三任务书与28轮对话流为依据，从零实现的角色记忆工作台。使用新的界面、规则引擎、状态机与持久化方式。

## 启动

本目录是参赛交付结构中的 `app/`。请保留它与根目录 `memory-rules.md` 的相对位置；程序读取根目录守则，网页展示与下载也使用该文件。

需要 Python 3.10 或更新版本，不需要安装第三方Python包或Node依赖。

双击 `start.bat`，浏览器打开 <http://127.0.0.1:8137>。终端保持运行；关闭终端即可停止服务。也可在本目录执行：

```powershell
python app.py
```

端口被占用时：`python app.py --port 8138`。无图形环境可增加 `--no-browser`。

## 怎样体验

界面以“记忆守护者_UI优化版.html”的三栏结构为依据，接入本项目的后端、侧边导航和守则。桌面从左到右分别为：**1 对话列表 → 2 对话与处理 → 3 当前记忆**。输入和助手回应使用对话气泡；本轮操作单独列出原值、现值及原因。各栏独立滚动，输入框保持在中栏底部。

顶部可以切换深色与浅色模式。较窄窗口通过“查看对话列表”打开轮次列表；手机或较矮窗口使用上下布局。

1. **官方材料回放**：启动时将官方28条原始输入逐轮交给新引擎，每条产生实际变化和快照，没有按轮次写死的操作答案。默认停在第6轮展示工作变更；可逐轮、自动播放或点击时间轴。这里的结果是本作品输出，不是官方标准答案。
2. **自由试验**：左侧“试验”打开空白工作区。输入介绍、工作变更、住址、目标或敏感信息，查看引擎实际判断。选择第三方/推送/系统来源可以测试边界。来源选择是模拟测试前提，不是真实登录鉴权。
3. **分支**：从当前轮次建立独立试验，继承当前快照。也可在官方回放中直接输入，发送时自动创建独立分支；查看历史轮次后发送同样会先分支。分支里的变化不会修改官方回放或其他工作区。
4. **待确认闭环**：记忆栏区分有效、待确认和待核实；自由试验里可以明确确认或删除具体条目。若正在查看历史轮次，后续操作会先创建分支。
5. **导出**：记忆栏右上角下载所选轮次的角色记忆；守则页可下载可注入的 Markdown 守则。
6. **现场演示**：通过“场景定位”跳转建档、工作更新、搬家、敏感信息、越权、遗忘、污染拦截及待核实场景。“新建试验”直接创建空白工作区；“以此为起点试验”继承当前快照。投屏模式放大关键内容，再次点击即可退出。
7. **守则可视化**：每轮“执行依据”列出该轮及其实际变更引用的条款。点击条款直接查看正文；守则窗口列出全部9条，并标记本轮依据。内容从 `memory-rules.md` 读取，同时保留完整原文和下载入口。

## 设计边界

- 官方主人背景卡仅供理解，没有作为对话输入或预填记忆。`data/official.json` 只含从官方脚本提取的原话、轮次和来源。
- 默认模式是可解释的本地中文规则提取，支持的字段见 `engine.py` 的 SLOTS。它不等价于通用大模型：没有识别到稳定字段时会明确说明未写入，不能保证处理任意表达。
- 可选模型：右上角填写兼容 `chat/completions` 的接口地址、模型名与本次运行密钥。自由试验将向该地址发送脱敏后的输入与当前角色记忆。官方回放始终使用本地规则。模型输出需经过Schema、证据与状态校验；失败时明确显示降级。
- 密钥只保存在服务进程内存中，不写配置文件。重启需重新填写。完整银行卡与身份证不保存到角色记忆，也不宣称有完整凭据的加密托管。
- `.state/workspaces.json` 保存本应用沙盒与分支。它不是 TeleAgent 平台会话导出。本项目不生成或替代参赛要求的平台日志。
- 明确删除会清除该工作区指定属性的全部版本与快照相关内容；其他独立分支是单独的副本，不随之改动。官方原始测试素材作为固定输入资料，不在应用删除指令的操作范围。
- 本应用是本机单用户演示工作台，绑定127.0.0.1，来源按测试入口模拟。真实多租户部署需要服务端账户认证、权限管理及更严格的数据隔离。
- 页面只展示实际条目数与操作数量；测试通过不代表隐藏验证集成绩或泛化能力认证。

## 交付目录

```text
守忆/
├── memory-rules.md        可注入常驻记忆守则
├── memory-LIMING.md       官方28轮实际处理后生成的最终角色记忆
├── 策略说明报告.docx      策略报告
└── app/
    ├── README.md
    ├── start.bat
    ├── app.py             本地HTTP服务、工作区、导出与持久化
    ├── engine.py          记忆生命周期和规则校验
    ├── model.py           可选模型提取适配器
    ├── static/            界面
    ├── data/              官方输入，无预置操作答案
    ├── tests/             源码中的回归检查
    ├── 策略说明.md        报告内容的Markdown来源
    └── 验证说明.md        已有验证记录与限制
```

`log.json` 需在正式提交前另行放入交付根目录，当前按用户要求不处理，也不生成模拟文件。运行后独立试验保存在 `app/.state/`，不应包含在提交包中。

## 检查与重新生成

在本项目目录执行：

```powershell
python -m unittest discover -s tests -v
python app.py --export-baseline
```

第二条命令仅重新生成上一级交付根目录的 `memory-LIMING.md`，不调用外部模型。DOCX报告由现有策略说明整理；未声称完成TeleAgent平台深度使用验证。

有Node.js时，可检查页面内容逻辑（文档替身，不是浏览器排版测试）：

```powershell
python tests/prepare_ui_fixture.py
node tests/check_ui.cjs
```
