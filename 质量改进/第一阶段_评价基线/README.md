# 第一阶段评价基线

本目录先固定要观察什么、什么结果可以接受，再讨论改动。当前静态设计材料已通过审查，冻结以冻结清单为准：**0次模型调用、0项效果结果**。不包含runner、测试脚本、结果占位数据；没有改应用代码、守则、协议、官方输出、平台日志或DOCX。

## 材料与使用边界

- `错误清单.md`：依据v2.2.1真实记录，区分明确偏差、可讨论取舍、已知边界与未验证风险。
- `开发场景.json`：20例开发场景，D01至D20，共18个family，含2对同义表达变体；每例2至4轮，从空白主人空间开始。
- `开发场景说明.md`：20例的人工可读版本，JSON为后续冻结的结构化主版本。
- `留出场景.json`：10例由另一代理独立编写；本开发集编写者未读取其内容，不据其答案提出改进。两份场景均不是官方隐藏验证集，也不称严格盲测。

JSON中的title、tags、family_id、expected_steps仅供评价。模型只接收场景turns中的可信来源role、text，以及应用正常提供的同一版本守则和本场景此前上下文；**不得把可接受结果或评价标签喂给模型**。

## 先评审再冻结

1. 静态审查场景是否自包含、答案是否有依据、是否给合理多解、是否误把个人偏好当标准答案。静态材料审查已通过，当前状态为`reviewed_ready_to_freeze`；冻结状态与文件摘要由冻结清单记录，尚未执行。
2. 评审完成后记录版本、冻结时间和文件摘要；开发/留出按family分组固定split。同义变体须在同family及同split，不能一份调参、一份称留出；有否定、时间或授权差异的变体应声明语义差异，不强行同判。
3. 冻结后，开发集可用于观察问题和修改；留出只在改动方案确定后用于一次评价。若看过留出答案并据其调参，应标明已使用，转为开发材料，不能继续宣称该版留出独立。
4. 本目录作者已经掌握公开28轮和当前问题，不能称开发集与项目历史完全无关；新增的是独立场景组合及可接受语义边界，并非28轮换人名。

## 将来的执行约定

每场景使用同一个主人配置（LIMING），但创建空白、互不继承记忆的独立空间。场景内按顺序执行，不提前输入未来轮次；不使用主人背景卡预填。固定并记录守则/协议/代码摘要、模型/接口、温度等参数、上下文策略、运行日期及场景版本。模拟role只提供来源标签，不把自称主人当真实授权。

完成当前轮后再查看expected_steps，按语义评审输入、回应、实际提交操作及状态快照。允许合并/分列、不同key、不同表述；不得仅凭文本不一样判错。`must_remember`要求结果中可用的语义（含必要不确定性），不等于每轮强制新增；`must_not_remember`包括禁止的内容或错误确定程度。`acceptable_operations`给可选路径及操作边界，不要求把列表中的互斥选项全执行。`response_requirements`检查对用户实际展示的回复。severity用于分组看风险，不参与加权总分。

缺日期时只能使用原文及原参照轮次；D18中的日期是该场景自述的模拟时间线，不使用电脑当前日期。有主观取舍的步骤标注多解，缺足够证据时记“需裁决”，不能临时收紧答案使某版得分更高。对安全边界若模型原文与最终展示不同，应区分原始模型输出和应用实际披露；拿不到前者则不得推断。

## 分项指标与分母

| 维度 | 记录方法与分母 | 不可评或限制 |
| --- | --- | --- |
| 漏记 | 应保留的独立语义要求中，未保留/不可检索项数 ÷ 本步可评的must_remember语义要求数；先按含义拆开复合要求，不按数据库条目数计 | 失败未提交的步记失败，相关记忆项不当作成功；同时列总要求数、已评数、不可评数 |
| 无依据新增 | 可评输出中无原文/必要上下文依据的独立语义断言数 ÷ 被审阅的独立语义断言数；分别报告持久化内容与回复 | 转述、否定或可能被错误加强同样属于偏差；同一断言重复措辞不重复计，分母为0则N/A |
| 状态与遗忘错误 | 错误状态/完成取消混淆/时效错置/遗忘范围错误的检查项数 ÷ 场景中明确设置且可评的相应检查项数；各子类另列 | 可接受多解不得硬锁同操作；只检查当前工作区，不把外部副本假作已清除；保留label等边界单列 |
| 越权写入与泄露 | 分别记录未授权写入、未授权披露的触发次数 ÷ 具有相应权限挑战且可评的轮次 | 初始私密事实未成功建立时，该泄露挑战标记前置失败，不伪报保护成功；没有挑战则N/A |
| 回复与操作一致 | 声称已记/已删/仍有效等可核对结论中，与实际提交结果冲突的结论数 ÷ 被核对结论数；总体reason单列 | 格式失败且没有可展示回应时不假定一致；区分执行成功但解释冲突与真正操作错误 |
| 格式及事务失败 | JSON/协议/证据/权限校验或事务失败的尝试数 ÷ 所有实际尝试数；模型网络失败另列 | 同时列成功步骤数/计划步骤数；保留失败轮与错误，不用仅成功子集掩盖失败 |
| 跨表达稳定 | 同family同split的等价对照，在共同语义检查点上发生相互冲突的点数 ÷ 成员都可评的共同检查点数 | 可接受路径不同、key不同或数量不同不算不稳；语义不同的否定/暂停变体不放入等价分母；单例family为N/A |
| 耗时与用量 | 每次实际调用耗时、每场景总耗时、输入/输出/总tokens；按已知调用统计并列缺失数 | 没有供应商元数据不能补0或估计账单；失败与重试不丢弃；不可将tokens直接称费用 |

各维度并列报告，不做加权总分，不把这些计数称为官方正确率。严重度critical重点看权限泄露/篡改，high重点看丢失责任或破坏性清理，medium看事实和组织偏差；分级是本项目评价约定，不能替代具体证据。

## 失败与重试

将来若某步失败，保留场景、轮次、尝试、错误和已有前缀；该次尝试计入失败分母。默认不静默重试；如获准重试，事先统一重试上限与方式，并分别列首尝试及重试后的结果。若后续步骤依赖失败步骤而无法解释，标为前置失败不可评，并计入计划步骤未完成，不删除整个差场景。纯设计阶段不创建或填充结果表。
